# v0.3 개선 검토 기록

2026-11-16 사용자는 제출을 마친 데모를 실제로 사용할 수 있는 앱으로 개선하도록 요청했습니다. 이번 검토는 원래의 차량용 즉흥 외출·여행 범위를 유지하며, 전경 위치·검토한 실제 장소·거리와 시간의 구분·실패 복구를 다룹니다. 제출 APK와 서명 신청서는 변경하지 않습니다.

## 검토 방식과 실행 근거

context-repair 회의의 명시적 후속으로 Sol·Opus·Astra·Sonnet·Argon을 지정해 실제 2라운드 아고라를 완료했습니다. 지정한 모델 5종의 응답, 실제 호출 10건, 실패 역할 0건, 최종 보고서의 인용 10개와 원문 연결을 검증했습니다. Sol은 중재자·서기, 나머지 네 모델은 기획·개발·디자인·리스크 역할입니다. 서로의 발언을 읽는 토론이며 독립적인 5표나 고객 조사로 표현하지 않습니다.

사용자 원안과 기각 이력을 보존한 기준문서 v2 **2,267자 전체**가 저장된 회의와 정확히 일치했습니다. 실제 실행 직전 컨텍스트 **12,689자**와 해시를 공개 저장소 밖에 보존했습니다. 첫 생성 요청은 Antigravity 연결 판정으로 실패했고 재확인 후 생성했습니다. 모델 응답을 받기 전 성공했다고 기록하지 않았습니다.

모델 식별자는 `gpt-6.1-sol`, `claude-opus-5-5-medium`, `gpt-6-astra`, `claude-sonnet-5-5-medium`, `gemini-4-argon-medium`입니다. Codex 모델명은 요청값, Antigravity 모델명은 CLI 보고값입니다. 회의의 사용자 결정 상태는 변경하지 않았습니다. 카탈로그와 현재 위치 기준값은 1라운드 중 추가 자료로 제공했고, 2라운드에서 이를 반박·보완했습니다.

## 실제 의견과 정정

| 역할·모델 | 우선 권고 | 반론·정정 |
| --- | --- | --- |
| 기획 · Opus | 상태별 복구, 출처·검토일·대표점 고지, 데모 분리 | 처음 제안한 기기 내 재실행 집계는 보류. 선택 이유와 한계 이해를 관찰하는 과업으로 변경 |
| 개발 · Astra | 단조 시계 위치 검사, 권한·후보 변경 뒤 지연 응답 폐기, 내비 실패 시 명시적 재시도 | 재실행 횟수만으로 효용을 입증할 수 없다고 지적. 조회·표시·내비 확인에서 같은 기준을 적용하도록 권고 |
| 디자인 · Sonnet | 등록 공원 범위와 미확인 시간 표시, 오류별 다음 행동, D의 설정 조작 제거 | ‘거리순’은 기분별 재정렬과 다르고, 소수 거리와 긍정 결과 문구가 과도한 확신을 줄 수 있다고 지적 |
| 리스크·카피 · Argon | 대표점·출처·실시간 미확인, 오류 복구 문구, 샘플 자동 대체 금지 | ‘세 곳의 재방문 가치가 없다’는 초기 단정을 철회하고 가치 제한 위험과 효과 미검증으로 정정 |
| 중재·서기 · Sol | 원안·기각 이력 유지, 구현 우선순위와 시험 가능한 조건 정리 | Argon 초안의 ‘2분 이상’ 경계·D 버튼·‘오차 포함’ 문구도 미해결로 남겼으며 합의로 덮지 않음 |

이번 권고는 위치를 받는 기능보다 **잘못된 위치·부족한 데이터로 확정적인 추천을 하지 않고, 실패했을 때 다음 행동을 설명하는 흐름**을 먼저 완성하자는 것입니다. 세 공원의 대표점으로 안내하면 도착 전에 진입로를 다시 찾을 수 있다는 불편은 고지만으로 해결되지 않습니다. 카탈로그 확대와 차량 입구 검증은 후속 과제로 남습니다.

## Argon 문구 교정

회의 뒤 실제 Argon 호출 1회로 구현 조건을 다시 주고 문구를 교정했습니다. 전체 프로젝트 기준문서와 입력 해시를 함께 보존했습니다. 응답에 서로 다른 JSON 두 개가 들어 있어 자동 채택하지 않았으며 원문을 모두 보존하고 직접 비교했습니다. 정상적인 D 상태의 명시적 내비 확인을 유지하고 **오류 복구용 권한·설정·재시도 버튼만 D에서 숨기는 첫 안**을 편집 선택했습니다. 서로 다른 두 응답을 독립된 의견 두 개로 세지 않습니다.

| 상황 | 채택할 문구의 기준 |
| --- | --- |
| 진입 | ‘내 위치로 공원 보기’와 서울·과천 등록 공원 3곳·직선 50km 범위를 함께 표시 |
| 결과 있음 | 현재 위치와 선택한 기분 기준으로 제안했음을 설명. 모든 결과가 거리순이라고 표시하지 않음 |
| 권한 거절 / 차단 | ‘권한 요청이 거절되어’와 ‘설정에서 권한 허용’을 구분. 재요청 버튼과 실제 설정 이동을 각각 연결 |
| 기기 위치 꺼짐 | 권한 거절과 섞지 않고 기기 위치 설정으로 안내 |
| 오래됨 / 오차 큼 | 경계가 어긋나는 ‘2분 이상’ 대신 ‘오래된 위치’ 사용. ‘오차 포함’ 대신 ‘위치 오차로 달라질 수 있어요’로 설명 |
| 결과 없음 | 주변에 장소가 없다고 단정하지 않고 등록한 공원 중 해당 거리·조건의 결과가 없다고 설명 |
| 내비 확인 | ‘주차장 입구가 아닌 공원 대표 위치’임을 명시. 정상 후보의 D 확인 동작은 유지 |
| 샘플 | 현재 위치와 무관한 예시임을 표시하고 사용자 선택 없이 전환하지 않음 |

문구는 상태와 실제 버튼 동작이 일치해야 하며, 글자 수를 줄일 때도 이 의미를 보존합니다. 아직 사용자 이해도나 실차 주시 부담을 검증한 것은 아닙니다.

## 이번 구현의 판단 기준

| 항목 | 검토 기준 |
| --- | --- |
| 실제 장소의 범위 | 서울숲·월드컵공원·서울대공원 세 곳. 실시간 전국 검색으로 표현하지 않음 |
| 좌표의 의미 | 공원 대표점이며 검증된 주차장 입구가 아님. 내비 인계 전에 이를 설명 |
| 위치 | 전경의 명시적 사용, 신선도·정확도 검사, 철회·중지 후 지연 응답 무효화 |
| 거리 | 대표점까지의 직선거리. 정확도가 낮은 위치를 과도하게 정밀한 숫자로 표현하지 않음 |
| 시간 | 경로 시간이 없으면 왕복 가능·체류 시간을 계산하지 않고 미확인 상태로 표시 |
| 복구 | 권한 거절·위치 꺼짐·미지원 지역·빈 결과에서 샘플로 자동 전환하지 않음 |
| 주행 | 키보드·권한 설정을 유도하지 않고 최소 요약과 별도 내비 확인 유지 |

## 독립 코드 검토 기준

Android는 대략적 위치만 허용할 수 있고 정밀에서 대략적으로 변경하면 프로세스가 다시 시작될 수 있습니다. 권한은 해당 기능을 선택했을 때 요청하고 실제 부여 결과로 분기해야 합니다. [Android 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions/runtime)

위치 나이는 부팅 이후 단조 시계로 비교하고, 정확도·mock 표식을 별도로 처리합니다. 시스템 시간 변경이나 오래된 fix를 현재 위치처럼 사용하지 않습니다. [Android Location](https://developer.android.com/reference/android/location/Location)

이번 검토에서 확인할 시험은 위치 나이·정확도 경계, 권한 철회 후 늦은 응답, 실제/샘플 전환 중 이전 후보 무효화, 지역 밖 결과 없음, 시간 조건이 있는 실제 장소의 미확인 표시, D/P 및 미확인 차량 상태 전환입니다. 실행하지 않은 시험은 통과로 표시하지 않습니다.

소스 검토에서는 다음 사항을 구현 담당자에게 전달했습니다. 완료 표시는 실행 시험 결과와 구분합니다.

| 발견 사항 | 조치 상태 |
| --- | --- |
| 영구 거절의 ‘설정’ 버튼이 권한 요청만 반복하는 경로 | 앱 권한 설정·기기 위치 설정으로 나누는 코드 반영 확인. P/known/foreground 검사 및 복귀 후 자동 동의 금지 포함 |
| 최대 5km 오차를 허용하면서 소수 거리로 표시 | 정수 km 또는 1km 미만 표시와 오차 고지 코드 반영 확인. 실제 표시값이 정확한 거리를 보장하지 않음 |
| 실제 장소의 이동시간이 없는데 ‘조건에 맞는 곳’이라고 표현 | 실제 장소+제한 시간은 ‘이동 시간 확인이 필요한 곳’으로 구분하는 코드 반영 확인 |
| 유효 위치의 갱신 진행 문구만 바뀌어도 확인창이 닫히는 키 구성 | 선택 근거를 fix·권한·후보 등으로 좁혀 진행 문구만 바뀌는 경우를 제외한 코드 확인 |
| 위치 기능을 끈 경우에도 이전 유효 fix를 READY로 유지할 수 있는 정책 | 제공자 꺼짐은 즉시 fix 무효화하고 전경에서 설정 변경을 관찰하도록 수정 확인. 일시 실패의 짧은 유지와 구분 |

검토 대상은 실제 새 소스이며 제출 APK나 신청서를 변경하지 않았습니다. 최종 빌드·기기 시험 수치와 수정 완료 여부는 프로젝트의 실행 기록을 기준으로 확인합니다.

반복 사용에서는 앱을 새로 열 때마다 정차 후 위치 사용을 다시 시작해야 하는 부담도 검토했습니다. 사용자가 정차 중 명시적으로 선택한 ‘앱을 열 때 내 위치 사용’ 선호 bool만 보존하는 코드가 추가되었습니다. 저장소가 `use_on_launch` bool 하나만 다루고, 시작 시 현재 권한을 확인하며 자동 권한 팝업이 없음을 소스로 확인했습니다. 샘플 선택·OFF·권한 철회는 선호와 위치를 정리하고, 백그라운드에서는 센서 요청을 중단합니다. 실제 D 콜드스타트·권한 철회·샘플 복귀 시험은 실행 기록에서 확인합니다. 이는 추가 동의의 법적 의무를 주장하는 것이 아니라 반복 사용과 제어를 분명히 한 설계입니다.

다음 개발 순서와 효과 검증은 [로드맵](ROADMAP.md)을 따릅니다.
