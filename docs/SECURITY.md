# 보안과 개인정보

공개 저장소라는 사실만으로 앱이 취약해지는 것은 아닙니다. 이 프로젝트에서 점검할 대상은 비밀값과 개인정보의 노출, 불필요한 권한, 외부 입력, 차량 기능의 오용, 잘못된 성공 표시입니다. 아래 원칙은 보안 인증 또는 완전한 침투 테스트를 의미하지 않습니다.

## 현재 시연 범위

추천은 오프라인 고정 예시로 재현하며, 회원가입·사용자 계정·자체 서버·운영 API 키를 사용하지 않습니다. 런타임 위치 권한, 분석 SDK, 영속적인 이동 이력이 없습니다. 실제 내비게이션은 Pleos NaviHelper 권한을 이용하는 별도 플랫폼 경계입니다. 최종 병합 manifest와 release APK 검사 결과는 [테스트 기록](TEST_PLAN.md)에 남깁니다. 예시 장소나 시간은 개인의 실제 이동 기록에서 추출하지 않습니다.

마음 원문은 최대 120자의 일시적인 입력입니다. UI는 원문을 저장 가능한 상태·설정·데이터베이스에 보관하지 않고 로그에도 기록하지 않습니다. Gleo 요청 객체의 문자열 표현은 원문 대신 `hasFeeling`만 표시하고, 응답 payload도 원문을 되돌려 보내지 않습니다. 선택된 마음 유형과 시간 조건의 화면 복원 상태는 원문과 구분합니다. 로컬 키워드 연결은 감정 진단이나 개인 성향 추론을 수행하지 않습니다.

## 저장소에 포함하지 않는 자료

- 개인 연락처, 이메일, 신청서, 개인정보 동의서, 서명 이미지, 인증 문서
- 운영 API 키, 토큰, 쿠키, 세션 정보, 비밀번호, 개인키·서명 keystore
- 로컬 SDK 경로, 개발 PC 설정, 원본 실행 로그, 디바이스 식별자
- 내부 기획·회의 시스템의 데이터베이스, 원문 로그, 대화 기록, 백업
- 사용자의 현재 위치, 이동 이력, 계정 정보, 차량 식별 정보

APK 파일명에 사용한 출품자 이름은 제출 파일 식별을 위한 명시적으로 허용된 정보입니다. 그것을 근거로 다른 개인정보까지 공개하지 않습니다. `.gitignore`는 실수 방지 장치이며 이미 커밋한 비밀값이나 APK 안의 문자열을 제거하지 않으므로, 추적 파일·Git 이력·최종 APK를 별도로 확인해야 합니다.

## 비밀값과 배포 서명

앱 바이너리에 넣은 값은 사용자가 추출할 수 있다고 가정합니다. 서버 권한을 가진 비밀 키를 `BuildConfig`, resources, assets, 코드 난독화에 숨기는 방식으로 보호하지 않습니다. 실제 외부 서비스가 추가될 때는 클라이언트 키의 사용 범위를 제한하고, 서버 비밀값은 서버의 환경 변수나 비밀 관리 기능에 둡니다. 키가 노출되면 파일 삭제만 하지 말고 먼저 폐기·교체하고 이력과 배포 산출물까지 점검합니다.

제출용 서명 키와 비밀번호는 로컬·CI의 보호된 저장소에 보관합니다. 서명에 실패했거나 debug 키를 사용한 APK를 정상 운영 배포본으로 설명하지 않습니다. release 빌드 종류와 서명 확인 결과를 함께 기록합니다.

현재 Gradle 구성은 로컬 `keystore.properties`가 있을 때만 제출용 서명 설정을 읽습니다. 이 파일과 키 파일은 공개 대상에서 제외합니다. 키 설정 없이 만들어진 unsigned release APK는 서명·설치 가능한 제출본과 구분합니다.

## 앱 경계

| 경계 | 통제 방침 |
| --- | --- |
| Android 권한 | 현재 기능에 필요한 권한만 선언. 위치·마이크 등 실제 취득 기능이 없으면 요구하지 않음 |
| Activity와 외부 입력 | 실행에 필요한 launcher 이외의 컴포넌트를 불필요하게 export하지 않음. 향후 딥링크 인자는 길이·형식·범위를 검증 |
| 네트워크 | 실제 기능 추가 전까지 의존하지 않음. 추가 시 TLS, 명시적 호스트, 타임아웃 및 실패 상태 적용 |
| 로그와 분석 | 개인 위치·입력·토큰을 기록하지 않음. 원본 로그를 공개 증빙으로 올리기 전에 제거·요약 |
| 저장 데이터 | 필요한 최소 설정만 저장. 실제 계정 도입 시 토큰 보호 및 공유 차량에서 로그아웃·초기화 제공 |
| 차량·내비 연동 | 기능 지원, 권한, 주행 제한, 사용자 행동, 호출 결과 확인. 미연동 데모는 실제 제어와 구분 |

현재 소스 manifest에는 내비 경로 요청·검색 권한만 선언되어 있고, `allowBackup=false`, `usesCleartextTraffic=false`로 설정되어 있습니다. `MainActivity`는 launcher와 Gleo의 `FIND_BREAK_PLACE` 요청을 받기 위해 export되어 있으므로 모든 수신 입력을 신뢰하지 않고 검증합니다. 그 행동으로 내비게이션이 자동 시작되지는 않습니다.

release 병합 manifest에서도 위치·마이크·INTERNET 권한과 debug 선언이 없음을 확인했습니다. AndroidX가 추가한 초기화 provider는 `exported=false`입니다. ProfileInstallReceiver는 `exported=true`이지만 `android.permission.DUMP`로 보호되며, 일반적인 무권한 외부 호출 지점과 구분합니다. 내부 동적 receiver 권한은 signature 보호 수준입니다. 최종 APK가 갱신되면 같은 검사를 반복합니다.

`allowBackup=false` 외에도 `backup_rules.xml`과 `data_extraction_rules.xml`에서 앱 데이터의 cloud backup·device transfer 영역을 명시적으로 제외합니다. 자동 테스트 67개 중 Gleo 입력·응답의 실제 Android 시험은 27개이며, 원문 비노출 계약도 검사합니다. 자동 시험 수는 전체 보안 취약점이 없다는 인증이 아닙니다.

Pleos 보안 가이드는 공유 차량의 계정 전환, 필요한 정보만 수집, 토큰 보호, 개인정보 로그 제한을 요구합니다. 이 데모에 계정이 없다는 사실은 추후 계정·위치·분석 기능의 보안 요구까지 해결했다는 뜻이 아닙니다. [공식 보안·개인정보 설계](https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/security-privacy)

## 공개와 권리

공모전의 소스 열람 요구와 자체 코드에 대한 오픈소스 재사용 허가는 서로 다른 결정입니다. 별도 `LICENSE`를 추가할 때는 저작권자가 허용할 범위와 의존 라이브러리·제3자 자산의 조건을 확인합니다. 공개 시 사본과 포크가 생길 수 있으므로 공개 기간이 끝나도 사본의 회수를 보장하지 않습니다. [GitHub의 라이선스 설명](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

공모전 운영 안내는 API 키를 저장소에서 제외하고 자체 서버 소스를 제출하지 않을 수 있음을 명시합니다. 비공개 자료를 문서에 링크하거나 압축본에 덧붙이지 않습니다. [공모전 추가 공지](https://appdevchallenge.auto-hmg.io/notice/c0a1a000-2026-4923-8000-000000000007)

## 검사와 한계

공개 전에는 파일 목록, 민감한 파일 확장자, 알려진 토큰·키 패턴, 외부 endpoint, manifest의 권한·export·backup·cleartext 설정, 의존성, APK의 서명·debuggable 상태를 확인합니다. 자동 문자열 검사는 모든 비밀값을 찾는다고 보장하지 않습니다. 발견 항목을 기록할 때 실제 비밀값을 복사하지 않고 파일 경로·종류·조치만 기록합니다.

실차 보안 시험, 공급망 전체 감사, 악성 앱과의 상호작용, 운영 서버 침투 테스트는 현재 별도 검증 범위입니다. 구현·실행에 근거한 관찰만 [검증 기록](TEST_PLAN.md)에 기록합니다.
